# Face Auth API Contract (Register + Login)

This is the complete frontend-backend contract for Face ID in this project, including:

- required fields
- all face APIs
- request/response payloads
- full working flow from UI to JWT login

## Scope

Implemented frontend endpoints:

- `GET /api/auth/face/status`
- `POST /api/auth/face/register`
- `POST /api/auth/face/login`

Configured from:

- `REACT_APP_FACE_AUTH_API_BASE_URL`
- fallback: `https://localhost:7095`

---

## 1) End-to-End How It Works

### A. Face Registration Flow

1. User clicks `Register Face ID`.
2. Frontend opens camera modal and collects:
   - `LoginName`
   - `ClientCode`
3. Frontend loads face models and starts webcam stream.
4. Frontend captures:
   - `Descriptor` (128 float vector)
   - `ImageBase64` (JPEG frame as base64 data URL)
5. Frontend calls `POST /api/auth/face/register`.
6. Backend stores template mapped to `LoginName + ClientCode`.
7. Backend returns success message.

### B. Face Login Flow

1. User clicks `Sign in with Face ID`.
2. Frontend resolves input values:
   - from login form / modal / stored hint
3. Frontend calls `GET /api/auth/face/status`.
4. If not registered:
   - frontend switches user to registration mode in same modal.
5. If registered:
   - frontend captures fresh `Descriptor + ImageBase64`.
6. Frontend calls `POST /api/auth/face/login`.
7. Backend validates biometric match and returns JWT token.
8. Frontend stores token and user info, then navigates to `/analytics`.

| `ClientCode` | string | Yes | Face modal | `LS000410` |

## 3) API: Face Registration Status

### Endpoint

- `GET /api/auth/face/status?LoginName={loginName}&ClientCode={clientCode}`

### Query Parameters

| Name | Type | Required | Example |
|---|---|---:|---|
| `LoginName` | string | Yes | `admin` |
| `ClientCode` | string | Yes | `LS000410` |

### Success Response

```json
{
  "IsRegistered": true
}
```

Frontend compatibility accepted for boolean:

- `IsRegistered`
- `isRegistered`
- `registered`

### Error Response (recommended)

```json
{
  "Message": "User/client not found.",
  "Code": "USER_NOT_FOUND"
}
```

## 4) API: Face Register

### Endpoint

- `POST /api/auth/face/register`

### Request Body

| Field | Type | Required | Validation |
|---|---|---:|---|
| `LoginName` | string | Yes | non-empty, trimmed |
| `ClientCode` | string | Yes | non-empty, trimmed |
| `Descriptor` | number[] | Yes | length must be 128 |
| `ImageBase64` | string | Yes | must be valid base64 data URL |

### Sample Request

```json
{
  "LoginName": "admin",
  "ClientCode": "LS000410",
  "Descriptor": [0.012, -0.094, 0.223, -0.011],
  "ImageBase64": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQABAAD..."
}
```

### Success Response

```json
{
  "Message": "Face registered successfully"
}
```

### Error Responses (recommended)

```json
{
  "Message": "No face detected in image.",
  "Code": "FACE_NOT_DETECTED"
}
```

```json
{
  "Message": "Descriptor must contain 128 values.",
  "Code": "INVALID_DESCRIPTOR"
}
```

## 5) API: Face Login

### Endpoint

- `POST /api/auth/face/login`

### Request Body

Same as face registration:

| Field | Type | Required | Validation |
|---|---|---:|---|
| `LoginName` | string | Yes | non-empty |
| `ClientCode` | string | Yes | non-empty |
| `Descriptor` | number[] | Yes | length = 128 |
| `ImageBase64` | string | Yes | valid base64 data URL |

### Sample Request

```json
{
  "LoginName": "admin",
  "ClientCode": "LS000410",
  "Descriptor": [0.019, -0.086, 0.204, -0.008],
  "ImageBase64": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQABAAD..."
}
```

### Success Response (must include token)

```json
{
  "Token": "<jwt-token>",
  "Message": "Face login successful"
}
```

### Token Requirements

JWT payload should include client identifier in one of:

- `ClientCode`
- `clientcode`
- `sub`

Reason: frontend reads one of these keys during `finalizeLogin()`.

### Error Responses (recommended)

```json
{
  "Message": "Face not matched.",
  "Code": "FACE_NOT_MATCHED"
}
```

```json
{
  "Message": "Face not registered.",
  "Code": "FACE_NOT_REGISTERED"
}
```

```json
{
  "Message": "Too many attempts. Try again later.",
  "Code": "RATE_LIMITED"
}
```

## 6) Backend Validation Checklist

Perform these checks in order for both register/login:

1. Validate `LoginName` and `ClientCode`.
2. Validate descriptor:
   - array exists
   - numeric values only
   - exactly 128 values
3. Validate/decode `ImageBase64`.
4. Apply tenant isolation using `ClientCode`.
5. For login:
   - fetch enrolled face template for user+client
   - compute similarity score
   - compare against threshold
6. If matched, issue JWT in existing auth format.

Suggested initial similarity tuning:

- cosine similarity threshold `0.45` to `0.60` (calibrate with real data)

---

## 7) Data Contract Notes

### Descriptor format

- Descriptor is frontend-generated from `face-api.js`.
- It is sent as JSON array (not binary).
- Decimal precision should be preserved; do not round aggressively.

### Image format

- Frontend currently sends JPEG data URL.
- Backend should strip optional prefix:
  - `data:image/jpeg;base64,`
  - before base64 decode.

## 9) Security and Compliance Requirements

- Treat face descriptor and captured image as biometric sensitive data.
- Use HTTPS only.
- Never log full `Descriptor` or full `ImageBase64`.
- Encrypt stored biometric templates at rest.
- Add rate limiting by user/IP/client.
- Keep password/passkey fallback enabled to prevent lockouts.
- Add retention and deletion policy for biometric records.
